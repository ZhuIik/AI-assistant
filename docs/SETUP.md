# Подробная инструкция по запуску

Этот документ описывает всё, что нужно, чтобы скачать репозиторий, поднять окружение и получить работающего бота с нуля — от установки зависимостей до полного пайплайна подготовки данных курса.

## 1. Установка окружения

### 1.1. Python и зависимости

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Требуется Python 3.11+. Для GPU-ускорения транскрибации и эмбеддингов нужна видеокарта NVIDIA с CUDA (см. `requirements.txt` — `torch`/`torchaudio` собраны под `cu121`). Без GPU всё тоже работает, но медленнее (Whisper и эмбеддинги пойдут на CPU).

### 1.2. ffmpeg

`scripts/convert_to_wav.py` вызывает `ffmpeg` напрямую из командной строки — он должен быть установлен и доступен в `PATH`.

### 1.3. Файл `.env`

Скопируйте пример и заполните реальными значениями:

```powershell
copy .env.example .env
```

| Переменная | Обязательна | Назначение | Пример |
|---|---|---|---|
| `BOT_TOKEN` | да, если используете Telegram-бота | Токен Telegram-бота от [@BotFather](https://t.me/BotFather) | `123456:ABC-DEF...` |
| `SERVER_URL` | нет (есть значение по умолчанию) | Адрес HTTP API, который опрашивает `bot.py` | `http://127.0.0.1:5000/chat` |
| `LM_STUDIO_BASE_URL` | нет (есть значение по умолчанию) | Базовый URL локального OpenAI-совместимого сервера | `http://localhost:1234/v1` |
| `LM_STUDIO_MODEL` | нет (есть значение по умолчанию) | Идентификатор модели, как он указан в LM Studio (`/v1/models`) | `google/gemma-4-e4b` |
| `ANNOTATE_MODEL` | нет (по умолчанию = `LM_STUDIO_MODEL`) | Модель для офлайн-разметки аннотаций (`prefill_annotations.py`) — можно указать более лёгкую/быструю модель, чем для чата | `google/gemma-4-e2b` |
| `EMBED_MODEL` | нет (есть значение по умолчанию) | Embedding-модель для RAG-индекса, тоже через LM Studio; multilingual — работает и с русским, и с английским | `text-embedding-nomic-embed-text-v1.5` |
| `HUGGINGFACE_TOKEN` | нет, только если нужна диаризация | Токен для загрузки модели диаризации `pyannote/speaker-diarization-3.1` | `hf_...` |

`.env` не должен попадать в репозиторий — он уже в `.gitignore`.

### 1.4. Локальная LLM (LM Studio)

Ассистент генерирует ответы через локальный OpenAI-совместимый сервер, а не через модель, встроенную в код.

1. Установите [LM Studio](https://lmstudio.ai/).
2. Скачайте instruct-модель, подходящую под требования из [README.md](../README.md#требования-к-llm-модели) (сейчас используется `gemma-4-E4B-it-GGUF`).
3. Скачайте и загрузите также embedding-модель `text-embedding-nomic-embed-text-v1.5` (или другую multilingual embedding-модель на замену через `EMBED_MODEL`) — она нужна для построения и поиска по RAG-индексу (`scripts/embed_kb.py`, `src/rag/retriever.py`).
4. Загрузите обе модели в LM Studio и включите **Local Server** (вкладка Developer → Start Server). LM Studio может обслуживать несколько загруженных моделей одновременно на одном сервере.
5. Проверьте, что сервер отвечает и видит обе модели:
   ```powershell
   curl http://localhost:1234/v1/models
   ```
6. Если имена моделей в ответе (поле `id`) отличаются от значений по умолчанию в `config.py` — укажите их явно в `.env` через `LM_STUDIO_MODEL`/`EMBED_MODEL`.

Без запущенного LM Studio сервер и бот всё равно поднимутся, но при вопросах, требующих генерации, будет отдаваться `_extractive_answer` — экстрактивный ответ прямо из найденных фрагментов, без LLM (см. [ARCHITECTURE.md](ARCHITECTURE.md)).

## 2. Добавление новых лекций в базу

### 2.0. Быстрый способ — один скрипт на всё

Для обычного добавления материалов не нужно вызывать каждый шаг вручную — `scripts/ingest_lectures.py` делает всё сам: конвертирует видео в WAV, транскрибирует, строит аннотации, заполняет метаданные и пересобирает RAG-индекс. Обрабатывает только новые файлы — старые лекции не трогает и не пересчитывает.

```powershell
# положить видео/аудио в data/raw/lectures/, затем:
python scripts/ingest_lectures.py

# с доп. параметрами транскрибации:
python scripts/ingest_lectures.py --model large-v3 --diarize --merge
```

Скрипт сам определяет, какие лекции новые (по появлению новых `data/segments/*.segments.jsonl`), и прогоняет через разметку/индексацию только их. Если новых файлов не нашлось — выведет сообщение и ничего не пересобирает.

Ниже расписан этот же процесс по шагам — пригодится для отладки, если что-то из шагов 2.1-2.6 нужно перезапустить отдельно (например, поправили аннотации вручную и хотите пересобрать только индекс).

### 2.1. Положить исходные файлы

Видео/аудио кладутся в `data/raw/lectures/`. Скрипт транскрибации сам разложит их по `unprocessed/` (ещё не обработано) и `processed/` (уже транскрибировано).

### 2.2. Конвертация в WAV (если исходник не WAV)

```powershell
python scripts/convert_to_wav.py data/raw/lectures/Lecture_1.mp4
```
На выходе рядом появится `Lecture_1.wav`.

### 2.3. Транскрибация

```powershell
python scripts/OpenAI-Whisper.py data/raw/lectures --model medium --language ru
```

Полезные флаги:
- `--diarize` — включить разделение по спикерам (требует `HUGGINGFACE_TOKEN` в `.env`, доступ к `pyannote/speaker-diarization-3.1`).
- `--merge --max-len 45 --max-gap 1.5` — объединять соседние сегменты одного спикера.
- `--device cuda|cpu|auto`, `--safe_int8` — управление вычислениями на GPU.

Результат: `data/transcripts/<lecture_id>.txt` (читаемый текст) и `data/segments/<lecture_id>.segments.jsonl` (структурированные сегменты с таймкодами и спикерами) — оба файла пишутся напрямую этим шагом, отдельно конвертировать транскрипт в сегменты не нужно.

### 2.4. Разметка на смысловые блоки

```powershell
python scripts/build_annotation_drafts.py --lecture-id Lecture_1
```

Сегменты объединяются в блоки по паузам, смене спикера и длине (не по значению, а по эвристикам — подробнее в [ARCHITECTURE.md](ARCHITECTURE.md)). Результат: `data/drafts/<lecture_id>.draft.jsonl`.

`data/drafts/` — промежуточная, регенерируемая папка (прямой вход для следующего шага 2.5), целиком в `.gitignore` и не хранится в репозитории постоянно. Если черновиков нет, а `data/segments/*.segments.jsonl` есть — просто перезапустите этот шаг перед 2.5.

### 2.5. Заполнение topic/summary/keywords/questions

```powershell
python scripts/prefill_annotations.py --lecture-id Lecture_1
```

По умолчанию каждый фрагмент прогоняется через локальную LLM (LM Studio) — модель определяет topic/summary/keywords/questions и точечно поправляет вероятные ошибки распознавания речи. Требует запущенного LM Studio (см. 1.4). Полезные флаги:

- `--no-llm` — не звать LLM, использовать только старые захардкоженные правила (например, если LM Studio не запущен, или для быстрой отладки).
- `--concurrency N` (по умолчанию 4) — сколько фрагментов размечать параллельно. На практике рост выше 4 не дал ускорения (упор в реальную производительность GPU, не в лимит параллельности) — поднимать не обязательно, даже если Max Concurrent Predictions в LM Studio выставлен больше.

**Если LLM-вызов для конкретного фрагмента не удался (сервер недоступен, модель вернула не-JSON) — скрипт автоматически откатывается на старые эвристические правила для этого фрагмента** (в лог выводится `[llm-fallback] ...`), весь прогон не падает.

Результат: `data/annotations/<lecture_id>.annotations.jsonl` — именно эти файлы использует индексация на следующем шаге. Поле `text` содержит очищенный LLM текст (или исходный, если сработал fallback), исходный текст до очистки сохраняется рядом в `text_raw`.

> **Важно про скорость:** LLM-размеченные ответы получаются заметно содержательнее шаблонных, но локальная генерация не мгновенная. Перед первым большим прогоном проверьте в LM Studio две настройки — они сильно влияют на скорость (подробнее в [ARCHITECTURE.md](ARCHITECTURE.md)):
> - **GPU Offload** на максимум (Context and Offload);
> - **Enable Thinking** выключен (Inference → Custom Fields), если модель это поддерживает — reasoning-модели тратят токены на скрытые "размышления" перед ответом, что заметно замедляет генерацию без пользы для качества разметки.
>
> С обеими настройками получилось ~19.5с/фрагмент последовательно и ~4.7с/фрагмент при `--concurrency 4` — на курс из нескольких тысяч фрагментов это порядка 4 часов. Без этих настроек то же самое может занять на порядок дольше. `--no-llm` даёт мгновенный, но менее точный результат.

> Есть альтернативный путь: `scripts/generate_annotations.ps1` делает шаги 2.4 и 2.5 за один проход, но только по старым эвристическим правилам, без LLM (PowerShell-эквивалент, без зависимости от Python-окружения).

### 2.6. Построение RAG-индекса

```powershell
python scripts/embed_kb.py
```

Читает **все** `data/annotations/*.annotations.jsonl`, строит эмбеддинги и FAISS-индекс в `data/datasets/rag_index`. Запускайте заново каждый раз, когда меняются аннотации.

Если `faiss` не установлен (или LM Studio недоступен) — индекс всё равно построится, но только в лексическом (без-векторном) режиме, о чём выведется предупреждение.

## 3. Запуск ассистента

```powershell
python scripts/server.py
```

Поднимет HTTP API на `http://127.0.0.1:5000`. Проверка:

```powershell
curl http://127.0.0.1:5000/health
curl -X POST http://127.0.0.1:5000/chat -H "Content-Type: application/json" -d "{\"text\": \"Привет\"}"
```

Telegram-бот (нужен `BOT_TOKEN` в `.env`):

```powershell
python scripts/bot.py
```

Локальная проверка без HTTP и Telegram — прямой CLI-диалог с движком:

```powershell
python scripts/chat_local.py
```

## 4. Типичные проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `Не удалось загрузить модельный пайплайн` в ответе | LM Studio не запущен или сервер выключен | Откройте LM Studio → Developer → Start Server |
| Ответ есть, но без содержательной генерации, только цитата фрагмента | Сработал fallback `_extractive_answer` — то же самое, что предыдущий пункт | Проверьте `curl http://localhost:1234/v1/models` |
| `RuntimeError: No annotations found` при `embed_kb.py` | В `data/annotations` нет файлов `*.annotations.jsonl` | Запустите `scripts/ingest_lectures.py` (или пройдите шаги 2.1–2.5 вручную), либо скопируйте готовые аннотации |
| `ffmpeg` не найден | Не установлен/не в `PATH` | Установите ffmpeg и перезапустите терминал |
| Диаризация падает с ошибкой авторизации | Не задан/не принят `HUGGINGFACE_TOKEN`, нет доступа к `pyannote/speaker-diarization-3.1` на HuggingFace | Запросите доступ к модели на HuggingFace, укажите токен в `.env` |
| GPU-режим Whisper падает на `cudnn_ops64_9.dll` | Не установлен/несовместим cuDNN 9 | Запустите с `--device cpu` либо поправьте установку CUDA/cuDNN |
